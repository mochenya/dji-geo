# DJI 上游异常点、边界约束与非主线接口备忘

本文汇总对大疆 GEO / FlySafe HTTP 接口实测发现的协议怪癖、空间与性能硬边界、安全风险、非主线旧域坑点以及未核实边界，供排障、容错设计与架构评审查阅。

---

## 1. HTTP 200 业务错与协议异常矩阵

上游在参数缺失、参数非法、超距、无记录等场景下**普遍返回 HTTP 200**，调用方绝不能仅依据 HTTP 状态码判断成败。

| 触发场景 | 端点系 | HTTP | 实测响应体特征 | 客户端必须采取的防线 |
| --- | --- | --- | --- | --- |
| 矩形搜索跨度超过 1000 km | `flysafe-api` | `200` | `{"code":1,"message":{"chinese":"请求错误","english":"Bad Request"},"data":"search distance greater than 1000 km"}` | 检查 `code !== 0`；注意 **`data` 从对象突变为字符串**；映射为确定性超距错，不重试 |
| 业务记录不存在 | `flysafe-api` | `200` | `{"code":5,"message":{"chinese":"记录不存在","english":"Record Not Found"},"data":null}` | 检查 `code !== 0` 且容忍 `data` 为 `null`；不重试 |
| 缺少核心参数 | `www-api` | `200` | `{"status":"422","extra":{"msg":"Params Missing!"}}` | 检查 `status !== "200"` |
| `drone` 非法或为空 | `www-api` | `200` | `{"code":101,"msg":"parameter invalid or blank \| drone","status":"200"}` | `status` 仍为 `"200"` 但缺少 `areas` 且带非 0 `code`；必须同时校验业务 `code` 与 `areas` |
| `point-info` 缺 `search_radius` | `www-api` | `200` | `{"code":400,"msg":"Signature is wrong","status":"200"}` | 缺参会误报签名错，见第 4 节 |
| 历史废弃路由（`/cn/api/geo/areas`） | 官网旧路由 | `302` | `Location` 指向 HTML 404 错误页 | **必须禁用自动跟随重定向**，并校验 `Content-Type` 为 `application/json` |

- **重试边界**：仅对瞬态故障（连接/读超时、网络异常、HTTP `429`、`5xx`）做带抖动指数退避；对 HTTP 200 业务错、302、非 JSON、结构校验失败等确定性异常**绝不重试**。

## 2. 空间检索与性能边界

1. **矩形查询硬跨度上限为 1000 km**：
   - `in_rectangle` 输入矩形对角线跨度超过 `1000 km`（等效 `radius > 500 km`）时直接返回 `code=1` 错误。
   - 自动切块客户端应把单分片最大对角线控制在远低于硬上限的安全值（如 `300–400 km`，本库默认 `350 km`），以同时规避高密度区响应过重与超时风险。
2. **服务端按外接圆查库，非严格矩形裁剪**：
   - `in_rectangle` 内部将矩形转换为中心点 + 半对角线等效圆检索，因此返回结果可能包含**落在矩形四角之外、外接圆之内**的少量周边区域。
   - 若调用方需要严格归属某一行政区边界，必须在客户端/业务层按行政多边形二次相交裁剪。
3. **高密度大框实测与隐式上限盲区**：
   - 跨度 `~100–200 km` 城市级至 `~450–700 km` 省级大框实测单次可返回数百条区域（实测最高 `413` 条），对多组高密度视口做 2×2 网格切块去重对照均验证 **0 漏召回**，未观察到小容量静默截断。
   - 但更高密度（如 `1000+` 条）是否存在隐式条数上限、分页协议或限流阈值均**未公开且未量化**。
4. **时延与偶发超时**：
   - 常规成功请求耗时约 `0.14–0.93 s`；高密度区域以及超大半径（如旧域 `search_radius=1000000`）实测出现 15 s 读超时。
   - 大框切块并发时任一分片重试耗尽应 **Fail-fast**，绝不静默返回残缺空域数据。
5. **跨地区策略差异与空数组语义**：
   - 同一接口在不同国家/地区的返回等级分布差异很大（部分地区以警示类为主，部分地区保留红色禁飞多边形），且厂商会按市场、机型与固件动态调整 GEO 策略。
   - 返回 `areas: []` 仅表示本次视口与机型组合未命中记录，**不能等价于“允许飞行”或“监管侧完整覆盖”**。

## 3. 安全、网络与数据新鲜度坑点

- **CORS 禁止浏览器直连**：上游 `Access-Control-Allow-Origin` 仅放行官方域名（现行矩形接口放行官网地图域，旧域接口放行官网商城域）。命令行/后端匿名可读不代表浏览器跨域可用，集成方必须通过服务端访问并自行做缓存与降级。
- **旧域响应头/Cookie 泄漏风险**：`www-api` 响应 JSON 中可能附带顶层 `header` 字段（含上游响应头或会话 Cookie）。若未来接触该域响应，落盘、打日志或转发前必须先剔除 `header`。
- **数据新鲜度盲区**：响应仅含 HTTP `Date` 与记录级 `begin_at`/`end_at`，**没有**单条几何的 `updated_at`、发布批次号或刷新周期承诺。跨年历史对照证实同一 `area_id` 的子区数量与限高配置会发生静默变更，无法从单次响应得知变更时间。

## 4. 非主线 / 旧域接口备忘（v0.1 明确不封装）

以下端点已完成实测探查，因位于废弃风险域、存在协议怪癖或与核心职责正交，v0.1 不予封装；记录于此避免重复踩坑：

1. **所有 GEO 接口与地理编码正交**：
   - 上游空域接口**只接受经纬度**，不接受文本地址或行政区划代码。官网前端也是先调用独立地名检索服务获取坐标，再调用 `in_rectangle`。
2. **旧域半径查询：`GET https://www-api.dji.com/api/geo/areas`**
   - 参数为 `lat`、`lng`、`search_radius`（米）、`drone`、`zones_mode=total`、`level`、可选 `country`；外层信封为 `{areas, country, lat, lng, radius, status}`。
   - **异常点**：区域对象本身与现行 `in_rectangle` 一致，但 `country` 参数省略或**错填**时服务端仍按实际坐标返回区域，却在顶层**原样回显传入的错误 `country`**——因此顶层 `country` 绝不可作为区域归属依据。
3. **旧域单点命中查询：`GET https://www-api.dji.com/api/geo/point-info`**
   - 语义确为服务端单点包含过滤：落点未命中时即使传大半径也返回 `areas: []`；命中容器时 `sub_areas` **仅返回命中的子区**，且父对象 `radius` 会被覆写为该子区半径。
   - **异常点**：虽为单点查询，但**必须传 `search_radius`**（传 `0` 即可）；省略该参数会触发极具误导性的 `{"code":400,"msg":"Signature is wrong","status":"200"}`。
4. **现行反馈原始记录：`GET https://flysafe-api.dji.com/api/qep/geo/feedback/area_raw`**
   - 传常规空域 `area_id` 返回 `code=5`（Record Not Found），仅用于特定反馈流，不可作常规区域详情接口。
5. **早期官网路径：`www.dji.com/cn/api/geo/areas`**
   - 已下线，返回 `302 Found` 跳转至网站 404 页面。

## 5. 已知未知清单与合规边界

### 5.1 尚未核实/未公开事项（Known Unknowns）

- **坐标参考系（CRS）**：未显式声明且未完成独立控制点校核（暂定 WGS-84）。
- **高度基准**：`height` 字段未核实属于真高（AGL）、海拔（MSL）还是相对起飞点高度。
- **内部枚举完整码表**：`type`、`data_source` 与 `level=10` 特殊限高的官方完整定义未公开。
- **服务端容量与风控阈值**：未量化单次返回条数上限、IP/出口频率限制、配额与地区可用性 SLA。
- **第三方授权条款**：未找到大疆面向第三方的免费 API 计划、数据许可或商业再分发授权。

### 5.2 合规红线

- 大疆网站服务条款对自动抓取、复制与再分发存在限制，生产或商业展示前须自行确认法律与授权边界。
- **设备围栏 ≠ 法定空域**：DJI GEO 仅反映设备侧飞控限制参考；中国大陆法定空域与飞行审批必须以民航局 **UOM / USS**（如现行行业标准 `MH/T 4066-2026`）及属地监管公告/批复为准，产品展示上应将厂商 GEO 提示与法定空域结论明确分离。

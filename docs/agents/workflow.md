# 开发工作流

根据任务目标、风险和用户授权选择需要的活动；探索、讨论与实现可以迭代，不要求每次都经历固定阶段。

- **探索与讨论**：理解问题和现有实现；需要时研究上游、比较方案并与用户讨论。分析、审查和讨论任务保持只读。
- **计划与执行**：非简单变更先明确目标、约束、风险和验收依据；按授权范围实施。对数据库写入、部署、发布、推送等影响大或难以回退的操作，先提供具体方案供用户审查，获批后执行。
- **实现与验证**：新增或调整公共接口、数据模型与测试前，先对照 [GLOSSARY.md](../../GLOSSARY.md)、[architecture.md](architecture.md) 和 [coding-standards.md](coding-standards.md)。按风险验证核心行为；源码或配置变更完成后执行 [本地检查](development.md#本地检查与-ci)中的完整验收门禁。
- **文档与交付**：重要功能或行为变化时按[文档维护](development.md#文档维护)同步受影响内容；报告结果、验证和未解决的限制。需要提交时遵循 [Git 提交规范](development.md#git-提交信息)；涉及版本、构建或发布时查阅[发布说明](release.md)。
